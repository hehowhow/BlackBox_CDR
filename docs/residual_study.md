## 固定设计

- Book→Movie 复用 `book_movie_protocol_8564` 的训练/验证/测试用户和 ID 映射。
- Movie→Book 使用相同 60/20/20 冷用户规则，原始 ID 排序编码。
- Movie→Music 先删除源电影域中所有与音乐域共享的物品及其评分，再排序编码、划分。
  共移除 2,441 个源物品、35,333 条源评分，音乐目标域不删减。
  清洗后源域有 1,662,200 条评分，重叠用户由 18,031 降为 17,874；
  训练/验证/测试重叠用户为 10,724 / 3,575 / 3,575。
- 全部任务的目标训练排除验证、测试用户，保留所有目标域非重叠训练用户。
- 每个任务固定一个用户划分；训练和打乱种子为 2020、2021、2022。
- 清洗不使用评分值或测试划分；不重新做 5-core，不进行时间过滤。
- Book→Movie 测试集历史上已评估，本实验不是新的盲测。

## 模型与对照

在各任务目标训练集上计算物品均值，并以验证 RMSE 从
alpha ∈ {0,1,5,10,20,50,100} 中选择平滑强度：

```
baseline_i = (sum_i + alpha * global_train_mean) / (count_i + alpha)
prediction_ui = baseline_i + item_bias_i + source_residual_ui
```

目标侧统计量在训练期间固定；未知目标物品回退到固定基线。

| 组别 | 可训练部分 |
| --- | --- |
| fixed_baseline | 无 |
| target_bias | 仅物品偏置 |
| real | 物品偏置、Top100 列表编码器、目标物品向量 |
| shuffled | 与 real 同结构，但用户源列表对应关系在各划分内部打乱 |

源服务为 MF 内积模型：维度 10，Adam lr=0.01，batch=512，固定 10 epoch。
每个任务、每个种子都从头训练源服务，再查询全部重叠用户的 Top100 物品 ID。
真实与打乱学生复用同一服务输出。学生不接收评分分数、源模型参数或源评分历史。

学生源物品向量维度 32，按 1/log2(rank+1) 加权池化；MLP 为 32→64→32，
ReLU、dropout=0.1，输出与目标物品向量内积作为修正量。
MLP 最后一层和物品偏置初始为零，保证起始预测精确等于基线。
没有源列表的目标域非重叠用户只更新物品偏置。

全部学生使用目标训练 MSE、Adam lr=0.001、weight decay=1e-5、batch=2048，
完整训练 20 epoch；按验证 RMSE 选择 checkpoint，包括 epoch 0 的基线起点。
真实与打乱模型初始化和 minibatch 随机序列相同；每个种子独立固定一份置换。
置换在训练、验证、测试三组用户内分别构造，无自映射，保持各组列表分布。

框架 CUDA 算子未强制启用全局确定性，因此不把配对初始化/随机序列相同等同于
所有 CUDA 归约逐位可复现。多个种子用于观察训练波动。

## 防泄漏和评价

数据构造阶段可以读原数据以划分、校验；统计量和选择只依赖目标训练/验证评分。
源训练和学生进程的读取审计钩子禁止打开测试评分、原始目标档案。
学生额外禁止打开源 MF 权重和源训练评分文件。
每个学生先保存选定 checkpoint，再对只包含 ID 的测试特征生成预测。
三个任务、九个种子的全部选择冻结后，统一评价进程才读取测试标签。

GPU self-test 8565 已验证：零初始修正、配对初始化、源分支梯度可学习、
未知物品回退及源 MF 前向公式。正式运行逐轮检查数值有限性，校验文件哈希。

主评价为 RMSE，同时报告 MAE、每用户等权 MAE、预测分布与超出评分范围比例。
报告三种子均值和标准差；比较 real 与 baseline/shuffled/target_bias 的差异。
2000 次测试用户簇 bootstrap 给出配对差异的 95% CI，区间条件于这三个已训练种子，
不把三次训练视为三个独立测试样本，也不将平均预测集成误认为单模型表现。

“主指标支持源域增量”的预设条件是三项 RMSE 差异的 CI 上界均小于 0。
这只是当前任务的一轮证据；未做多任务多重检验校正，不支持普遍性结论。

## 入口与产物

新实验必须使用新的绝对路径，准备入口拒绝覆盖已有目录：

```bash
sbatch scripts/slurm_residual_prepare.sh /absolute/path/to/new-study
# 等预处理成功，再提交：
sbatch scripts/slurm_residual_train.sh /absolute/path/to/new-study
```

训练脚本申请 2 GPU、8 CPU，在 Slurm 分配的两个设备上运行两条顺序任务链，
不写死物理 GPU 编号。末尾自动统一评价。

- `experiment.json`：固定参数及执行代码哈希。
- `<task>/manifest.json`：清洗、划分统计及数据哈希。
- `<task>/baseline/selection.json`：仅用验证集选出的固定基线。
- `<task>/runs/seed_*/`：源服务、列表、置换、训练曲线、选定模型和预测。
- `train_0.log` 至 `train_8.log`：任务/种子执行日志。
- `<task>/results.json`、`summary.json`、`report.md`：最终结果，只有全部训练成功后生成。

运行目录的模型、数据、预测和日志不入 Git；小型协议、摘要可保留。
不再用旧二路划分 wrapper，历史模型和未清洗 Music 模型不参与本轮评价。
