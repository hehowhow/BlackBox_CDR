# LIST 的研究需求：从当前信息链路出发

日期：2026-09-26。本文基于已归档的 LIST v1、后续实验记录和本次公开文献检索。目的在于明确问题，再决定技术；文中的需求和推导不代表新增模型已经实现或验证。

当前方法依据：[主版本 outline](list_residual_v1_paper_outline.md)、[版本快照](current_list_version.md)。后续实验依据：[分段实验](list_segmented_experiment.md)、[簇数搜索](list_cluster_count_search.md)、[首轮原型结果](list_three_story_experiments.md)、[实施范围核对](list_implementation_alignment_audit_20260925.md)。

**主要判断。** 当前最清楚的核心需求是：在只能取得源推荐列表的条件下，识别并保留对目标评分有用的用户差异，使这些差异能够可靠地转化为超过目标物品均值的增量。是否需要概率分布、离散编码、更多查询或其他结构，要由它们解决的具体信息缺口决定。

我们已有证据支持源列表包含用户相关预测信息，但还没有证明这种信息全是语义兴趣、全局池化丢失是主要瓶颈，或列表接口具有正式隐私保证。

**一、当前链路实际做了什么**

> 源端根据用户生成 Top100 → 返回物品 ID 和排名 → 学生学习源 ID 向量 → 固定排名加权池化 → MLP → 与目标物品向量内积 → 修正目标物品普通均值。

记源列表为 L_u，源物品向量为 e(s_r)，则：

\[
\alpha_r=\frac{1/\log_2(r+1)}{\sum_{t=1}^{K}1/\log_2(t+1)},\quad
h_u=\sum_{r=1}^{K}\alpha_r e(s_r),\quad
\hat r_{ui}=\mu_i+\lambda\operatorname{MLP}(h_u)^\top v_i.
\]

学生只取得列表与重叠训练用户的目标评分；没有源历史、源分数、教师参数或物品文本。训练通过目标评分误差学习源 ID 向量、MLP 和目标物品向量，因此当前模型已经在学习目标相关性，不能把它描述成完全不考虑目标任务的源兴趣平均。

固定排名权重仍是一种结构先验：同一名次获得相同的直接池化权重。学生可通过向量方向、大小及后续网络调整其作用；所以“第1名权重大”也不等于它一定使目标评分升高。

本版使用固定查询快照，Top100 未过滤源端已交互物品，词表包含已查询验证/测试列表的无标签 ID。它不是对全新源 ID、持续变化服务和未来时间的完整部署验证。这个边界对理解下述需求很重要。

**二、沿工作流梳理需求**

“结构上存在”表示能由接口或公式确认该问题；它不等于该问题已经造成可测的主要性能损失。

| 环节 | 真正需要解决的问题 | 当前版本的处理与缺口 | 证据状态 |
| --- | --- | --- | --- |
| 获取列表 | 正确理解有限观测：什么被返回，什么只是未观测 | 只有截断顺序，没有分数差距、源历史或列表外偏好 | 信息限制确定；实际损失量未知 |
| 解释排名 | 区分源服务的推荐优先级与目标任务的信息价值 | 权重随源排名固定变化，目标相关性主要由可训练表示和评分监督学习 | 概念差异确定；更换权重能否改善未获一致支持 |
| 学习源 ID 表示 | 在有限重叠监督下学到可复用、能推广的模式 | 独立 ID 查表依赖训练支持；未知 ID 没有现成语义特征 | 学习支持问题存在；尚未证明是主要瓶颈 |
| 聚合列表 | 压缩后仍能区分目标评分真正不同的用户 | 单个32维池化向量可能混合信息，但也可能有效降噪 | 多分段、多簇未稳定改善；不能预设更细更好 |
| 使用源证据 | 判断何时源信息可信、何时应减小修正 | λ为全局验证选择值，未显式提供逐用户或逐物品的可靠性估计 | 全局控制的局限确定；异质损害程度未量化 |
| 适应列表变化 | 对无关的排序扰动稳定，对有用的偏好变化敏感 | 主要在冻结源DNN快照训练和测试 | 合理部署需求，尚无动态服务验证 |
| 决定采集量 | 仅在额外信息值得成本时继续获取 | 固定K对照已经运行；按需停止和候选集合查询尚未实现 | 条件性需求，取决于接口能力和真实成本 |
| 跨越访问边界 | 传递目标所需信息，同时限制指定的隐私泄漏 | 不共享源历史和参数，但按用户返回的列表仍携带个性化信息 | 尚无隐私攻击评估或正式保证 |
| 解释最终收益 | 分清评分校准、物品相关偏好和最终任务收益 | 已有MAE/RMSE和错配列表证据；未拆开用户整体偏移与物品区分能力 | 明确的论证需求，决定论文能声称什么 |

这些需求不意味着要给九个环节各加一个模块。更合理的做法是围绕一个主要缺口提出方法，其他需求用于约束它、解释它适用的范围。

**三、聚合到底需要向量，还是兴趣概率分布？**

首先要明确“分布”在描述什么。下面四种对象有不同意义，不能混用。

| 对象 | 含义 | 当前列表能否直接提供 |
| --- | --- | --- |
| 归一化聚合权重 α_r | 我们在计算中给不同排名多大权重 | 能，由人为公式得到 |
| 用户真实兴趣概率 | 用户喜欢某个物品、类别或兴趣模式的概率 | 不能直接识别；需要额外模型假设或观测 |
| 给定列表的表示不确定性 | 模型看到这份列表后，对用户表示有多少把握 | 可以尝试估计，但需要校准和验证 |
| 目标评分条件分布 | 给定源列表和目标物品，可能出现哪些评分 | 可以用目标训练监督建模；本版只输出点预测 |

α_r非负且和为1，所以数学上可以据此构造一份“列表上的加权经验分布”，h_u是其嵌入均值。但这只是我们定义的测度，不等于恢复了用户真实兴趣。

原因很直接：源分数(4.9,4.8,4.7)与(4.9,3.0,1.0)都会产生A>B>C的顺序，喜欢程度的间隔却完全不同。对源分数作严格单调变换也不改变排序。只有一次Top-K结果时，不能唯一恢复这些差距，更不能把差距直接当作概率。没有出现在Top-K的物品也不能一律标成用户不喜欢。

还有一个很具体的限制：对于长度相同、无缺失且ID不重复的完整列表，固定α_r的熵对所有用户都一样。因此直接计算这组名次权重的熵，不能度量哪个用户兴趣更多样，或哪个用户的表示更不确定。按可学习语义组汇总后的熵可以变化，但它依赖分组本身，也需要与目标用途对应。

[Ranking Distillation，KDD 2018](https://jiaxit.github.io/resources/kdd18ranking.pdf)与[RankDistil，AISTATS 2021](https://proceedings.mlr.press/v130/reddi21a.html)说明排序关系可以承载可学习知识。它们研究教师排序的传递，不支持把排名权重自动解释成真实兴趣概率；而LIST要预测另一套物品的评分，也无需完整复制源排序函数。

**对我们而言，更基本的需求是“目标任务所需的信息是否留下来了”。** 固定训练得到的μ_i，以平方损失为目标，在相同评价分布下，理想的列表残差函数为：

\[
f^*(L_u,i)=\mathbb E[R_{ui}-\mu_i\mid L_u,i].
\]

因此，编码器z=g(L)需要尽可能使：

\[
\mathbb E[R-\mu_i\mid L,i]
\approx\mathbb E[R-\mu_i\mid z,i].
\]

意思是：把整张列表换成z之后，不应丢掉影响目标期望评分的差异。这是平方损失下的条件均值要求，不要求恢复完整的源兴趣分布，更不要求还原全部历史。该推导是一个理想目标，不能保证当前有限数据、32维编码器或优化过程已经达到它。若以MAE为主，理想点预测对应条件中位数，不能原样使用条件均值结论。

分布表示只有在承担明确功能时才值得引入。例如，两个列表的加权中心相近，但其中对目标有用的模式不同；或者需要知道模型对某次修正是否有把握。前者是表达能力问题，后者是不确定性问题，不是同一需求。

一个容易忽略的细节是：如果只是把最终用户向量Z改成随机分布，评分仍取期望内积，则

\[
\mathbb E[Z^\top v_i]=\mathbb E[Z]^\top v_i.
\]

在均值固定时，方差不会直接改变这个点预测。分布训练可能改变学到的均值，非线性分布评分也可能利用高阶信息，但收益需要来自这些具体作用，不能仅凭“从向量升级到分布”推定。

[ComiRec，KDD 2020](https://arxiv.org/abs/2005.09347)从行为序列学习多个兴趣，用于候选召回；[STOSA，WWW 2022](https://arxiv.org/abs/2201.06035)则用高斯表示及相应交互方式建模序列中的不确定性。二者说明多兴趣与随机表示各自有具体任务动机。它们的输入是行为序列，我们的输入是服务输出的排序；不能把源推荐名次解释为消费时间顺序。

结合本地证据，目前不应把“恢复多峰兴趣分布”列为首要、已确认需求。分段实验没有整体改善，簇数搜索在两档β都选中单簇。它们不能否定一切分布表示，但已经削弱“全局向量太粗，所以必须拆得更细”这个预设。

**四、排名加权的更深需求：辨认跨域价值**

这里存在三种不同的量：

1. 源服务把某物品排在前面的程度。
2. 该物品或列表模式区别这个用户与其他用户的程度。
3. 该区别有助于预测目标评分的程度。

三者可能相关，但不能画等号。例如，某热门音乐在许多人的前排，对区分用户未必有帮助；某个较少出现的模式可能有区分度，但只与音乐口味相关，与电影评分无关。反过来，热门物品组合也可能有用，不能用“热门”直接判定应当删除。

因此更具体的需求是：**在只有ID、排名和目标训练评分时，学会识别用户相关且目标相关的列表证据，同时保留必要的稳定性。**

当前LIST已经通过目标监督部分实现这一点，问题是能否做得更稳、更容易推广。此前频次降权和目标相关加权没有一致改善，所以现在也不能把“热门污染严重”或“必须目标注意力”写成已经确认的缺陷。

[CUT，SIGIR 2024](https://arxiv.org/abs/2403.20296)用目标域用户关系约束跨域迁移，体现“源域相似不一定是目标域相似”的问题；[CDRIB，ICDE 2022](https://arxiv.org/abs/2203.16863)与[CoTrans，CIKM 2024](https://arxiv.org/abs/2409.19574)也分别研究共享信息和目标相关的源信息压缩。这说明“筛选有用信息”已有丰富先例，我们的切入点应落在**拿不到源行为、源向量或源分数时，如何仅从截断输出识别这种价值**。不能只增加一个IB损失便声称提出了全新问题。

源列表本身已经经过一次很强的压缩，再压缩学生表示既可能去掉无关信息，也可能毁掉有限信号。本地隐藏层VIB实验只出现局部小幅收益，未获一致改善；它不支持“还需要更强压缩”的结论。

与偏差校正相关的文献还提醒我们注意观测机制。[Unbiased Learning-to-Rank，WSDM 2017](https://www.microsoft.com/en-us/research/publication/unbiased-learning-rank-biased-feedback/)研究的是带位置偏差的点击反馈及其倾向校正。LIST的输入是教师输出名次，没有点击曝光倾向，1/log₂(r+1)不是逆倾向权重。不能借用同一名称就宣称已经完成无偏或因果迁移。

**五、表示学习的需求：少量监督下可复用，而非仅仅看起来有语义**

只使用源ID查表时，一个源物品被多少重叠训练用户的列表覆盖，直接影响它能获得多少任务监督。源目录很大、重叠用户少、少见ID多时，独立向量可能难学；列表组合查表又可能更稀疏。这是编码和参数共享值得研究的动机，但目前还没有足够分层结果证明它是本任务的主导误差来源。

[TIGER，NeurIPS 2023](https://papers.neurips.cc/paper_files/paper/2023/hash/20dcab0f14046a5c6b02b61da9f13229-Abstract-Conference.html)和[VQ-Rec，WWW 2023](https://arxiv.org/abs/2210.12316)提供了离散代码共享物品结构、促进泛化的相关思路。但二者使用物品内容来构造代码，当前LIST学生没有这些内容。若只根据已取得的列表共现和目标训练监督学习代码，应准确称为协同或任务驱动的代码，不能默认它具有经验证的人类语义。

由此得到的需求是：**让监督稀少但具有相关模式的物品能够共享有效统计，同时避免把目标上不同的物品过度合并。** SID可以是未来候选，简单参数共享也可能满足需求；离散本身不是目的。

对于训练后真正全新的源ID，如果既没有内容、已知映射，也没有足够共现观测，模型无法凭一个陌生编号知道它的含义。任何新方法都必须说明它靠什么信息推广，不能把代码化当作免费解决冷启动。

**六、源证据的需求：知道什么时候不该过度相信**

当前同一个全局λ作用于所有用户和目标物品。它能调节平均修正幅度，却不能表达某个用户的列表训练支持充分、另一个用户的列表几乎没见过。即使总体RMSE改善，也不保证每个用户都改善。

真正的需求是：根据推断时可见的信息，评估修正的可靠程度，并让“没把握”在预测行为上产生合适影响。列表中训练少见ID多、模式在训练中缺乏支持，可能是信号；但“可能”不能直接当作已经校准的误差概率。

这不等于必须增加逐条目注意力、复杂门控或多个专家。可靠性可以通过训练约束、选模或简单决策体现。若某种“置信度”与真实误差无关，给它加概率名字不会带来理论深度。

[On Calibration of Modern Neural Networks，ICML 2017](https://proceedings.mlr.press/v70/guo17a.html)表明神经网络输出的置信度需要单独检验。该文主要研究分类校准；对我们的评分回归，应检查误差、区间覆盖或修正收益与可靠性估计的关系，不能直接把分类ECE套成已完成的验证。

稳定性是另一层需求：相邻名次的小扰动可能只是源模型噪声，也可能包含有用差异。我们希望对无关变化稳定、对有用变化敏感。只有固定快照时，不能预先认定所有重排序都是无关噪声，也不能承诺跨源服务或时间变化稳定。

**七、隐私的需求：先明确保护对象和边界，再考虑SID**

“不传原始历史”和“接收方无法推断隐私”是两个不同性质。当前LIST满足前一种输入约束，后一种没有经过检验。

[Membership Inference Attacks Against Recommender Systems，CCS 2021](https://yangzhangalmo.github.io/papers/CCS21-RecommenderMIA.pdf)研究了推荐器仅暴露排序物品、没有预测概率时的用户级成员推断；其攻击还使用用户相关物品、辅助数据和影子模型。它说明列表接口仍可能支持隐私推断，不代表我们已证明仅一张LIST输入就能完成同样攻击。[RAP，WSDM 2020](https://arxiv.org/abs/1911.09872)则直接把推荐效用与用户私有属性推断放在同一问题中研究。

首先需要选择保护对象：

| 保护对象 | 具体问题 | 对当前工作的影响 |
| --- | --- | --- |
| 源端交互历史 | 接收方能否推断用户是否消费或评价过某物品 | Top100未过滤已交互项，应区分推荐与实际交互；仍需定义辅助知识和攻击目标 |
| 敏感属性或兴趣 | 能否从列表或表示推断不希望共享的属性 | 需要合法可用的评价标签或明确代理任务，不能凭空制造敏感标签 |
| 源训练成员身份 | 用户数据是否参加过源服务训练 | 与目标冷用户身份是不同概念，不能混用 |
| 用户跨域身份 | 能否把两个平台账号关联起来 | 本版接收方本就知道用户对应；若还要向该接收方隐藏对应，需重新设计协议 |
| 源服务模型资产 | 能否通过查询复制推荐逻辑 | 与保护用户隐私不同，不应混成同一个指标 |

近期[DBGRME，NeurIPS 2025](https://proceedings.neurips.cc/paper_files/paper/2025/file/cce7576bf51b6a156346156c0976e7f6-Paper-Conference.pdf)研究有查询限制、无需原训练数据的黑盒推荐模型提取。它支持“参数隐藏不等于输出完全不泄露模型知识”，但其合成查询能力和模型提取目标与当前LIST不同。

然后必须确定接收方看到了什么、保护在哪发生：

| 处理方式 | 可以研究的作用 | 不能据此声称 |
| --- | --- | --- |
| 目标端已收到ID，再训练SID | 紧凑表示、参数共享；如果第三方只见代码，也可研究后续披露风险 | 对已看过ID的目标端消除此前泄漏 |
| 源端或可信用户端先编码，只传代码 | 减少跨边界的直接物品身份披露 | 无需源端配合；或编码天然构成正式隐私保证 |
| 完整SID仍能唯一还原物品 | 与原ID不同的结构化表示 | 自动隐藏物品身份 |
| 只传粗代码或多对一分组 | 在任务效用与身份细节之间形成可测折中 | 一定隐藏敏感兴趣；或一定优于普通分组 |

TIGER的具体实现很能说明问题：当完整语义编码发生冲突时，它会增加一个区分token并维护映射，使编码能定位具体物品。这是检索需要，不是匿名化设计。见[原论文§3.1](https://papers.neurips.cc/paper_files/paper/2023/file/20dcab0f14046a5c6b02b61da9f13229-Paper-Conference.pdf)。如果接收方掌握映射，把ID换成这种完整SID可能只是换一种编号；即使不掌握映射，稳定组合也可能支持关联推断，风险大小需实测。

粗编码可能隐藏“具体哪首歌”，却继续暴露“哪类兴趣”。这是保护对象不同带来的差别，不能用编码更短、重建更难或某一个攻击器变差代替完整隐私论证。

[PPGenCDR，AAAI 2023](https://ojs.aaai.org/index.php/AAAI/article/view/25566)专门在跨域迁移中设计带Rényi差分隐私的生成过程，体现隐私应约束信息产生和共享机制。它使用的源数据访问和生成模块不能直接移植为现有列表接口的一部分。若未来要求差分隐私，需要定义保护单位、随机发布机制、隐私预算及多次查询组合；还要区分保护源训练数据与保护当前用户的个性化查询输入。

因此，隐私方向的正确需求可以表述为：

> 在明确接收方能力和保护对象后，能否让跨域传递的信息保留目标评分价值，同时减少对指定源端敏感信息的泄漏？

这可以构成独立研究主线。现在还不能断言必须引入SID，更不能只给现有加权聚合增加SID就把它命名为隐私保护LIST。若要向目标端隐藏原始列表，应在其接收列表之前处理；这需要源端或可信客户端配合，属于接口或部署设定的扩展。

更一般地，能预测目标评分的信息本身就含有某种用户差异。如果被保护属性与目标任务密切相关，两者可能存在冲突。目标应是保护指定的不必要信息，而不是同时承诺准确个性化和隐藏一切用户偏好。

[DeCoCDR，SIGIR 2024](https://zhouzimu.github.io/paper/sigir24-li.pdf)把云端召回与设备端重排分开，设备端可使用本地跨域数据。这提醒我们：信息在哪一端处理，本身就是研究设定的一部分。它不等于目标端只能看到源ID列表的LIST，也不能把设备端已有原始数据这一能力默认为我们具备。

**八、信息采集的需求：多问一次能解决什么不确定性？**

固定Top100没有考虑不同用户需要多少信息。但只有当额外查询确实可用、代价有意义时，按需采集才是实际需求。当前轻量学生没有被证明存在严重延迟或显存瓶颈，不能只为引入热门方法而宣称效率是主要痛点。

[Acquisition Conditioned Oracle，ICML 2024](https://proceedings.mlr.press/v235/valancius24a.html)研究按成本取得额外特征，以保持预测质量。这给出的需求是“预测边际价值与获取成本的比较”，并不是把K由100改成200。

针对LIST，应分清：

1. 若接口始终只返回同一份Top100，继续询问不会凭空产生新信息；此时只能研究现有输出的利用。
2. 若可按前缀继续获取，需要在没看后缀时判断继续的目标收益。先读完整列表再决定截断，是压缩使用而非减少源端采集。
3. 若可指定候选集合，需要说明这种额外能力；不同集合内的局部名次不能直接当作同一份全局名次。

本地固定K实验只能说明长度影响。学习停止策略和候选查询仍未实现，不应把它们写成已经验证成功或失败。采集效果还必须与同预算的简单获取方式比较，预算至少区分返回条目数和调用数。

**九、最终评分的需求：我们到底迁移了哪种用户差异？**

源信息可以帮助预测“这个用户习惯打低分”，也可以帮助预测“这个用户更喜欢电影A而不是电影B”。二者都是用户相关信息，但在推荐中的作用不同。

如果修正几乎只是用户标量a_u，则预测μ_i+a_u可降低评分误差；对于同一个用户，a_u给所有候选加上同一个数，并不改变按μ_i形成的排序。因此真实列表优于错配列表，不能单独证明已经学到细粒度语义兴趣或提高了目标Top-N排序。

本地历史统计特权诊断曾显示评分风格和活跃度统计有预测价值，但没有将各因素独立拆开；它也不是当前纯列表主版本的直接机制证据。参见[CDR有效性分析](cdr_effectiveness_analysis.md)。

此处的需求是让论文中的解释与实际增量相符：当前主张为冷用户评分预测，就以评分证据说话；若进一步主张物品偏好迁移或更好的推荐排序，应补对应证据。不能靠给32维表示或若干簇起兴趣名称来完成解释。

**十、哪些需求值得形成干净的研究主线**

| 候选主线 | 可以独立成立的研究问题 | 与已有结果的关系 | 判断 |
| --- | --- | --- | --- |
| 目标相关信息的保留 | 只有源端截断排序时，怎样保留能区分目标评分的用户信息，同时不过度拟合源排序和ID偶然性 | 直接承接主版本有效、复杂聚合未一致改善的证据 | 最贴近当前工作的主线；先具体化缺口，不预设分布或IB |
| 有把握地使用有限证据 | 只看列表时，怎样判断某次评分修正是否可靠，并在证据不足时控制它 | 本版只有全局λ；尚无个体可靠性结果 | 可以独立探索；先说明可信度服务于什么决策 |
| 尽量少披露仍可迁移 | 在明确隐私对象和接收方能力后，是否能减少发布细节并保持跨域效用 | 当前没有隐私评估；需要保护边界前移时会改变接口 | 独立分支，不作为主模型随手附加模块 |
| 按需取得信息 | 有额外查询能力时，怎样把有限预算用在更有目标预测价值的观测上 | 固定K仅是前置对照，核心方法未实现 | 有真实成本和接口支撑时再作为主线 |

前两条也不应自动合并成一个复杂模型。目标相关性回答“保留什么”，可靠性回答“相信多少”；找到哪个更像当前主要缺口，再选一个问题作为主线。

目前应降级的预设包括：必须拆更多兴趣簇；必须重建源用户的完整兴趣分布；必须压得更狠；必须用SID才更隐私；必须有Engram才更高效。这些都是待评价的技术或效果假设，不能先当作需求。

我的建议是首先使用下面这句需求描述组织后续方法选择：

> 源列表是源服务为自己的任务筛选过的有限输出。我们需要在不知道源分数和行为的条件下，识别其中对目标任务有用的用户差异，并把它们转换成能推广到新冷用户的评分增量。

如果转向隐私主线，则改成：

> 在不让接收方取得指定源端细节的条件下，保留完成目标评分预测所需的最少个性化信息。

两句话有不同约束和证据要求。前者优先保持当前ID/排名接口；后者可能需要源端或可信客户端发布不同信息。决定要解决哪一句之后，才有依据从经典理论和新技术中选择工具。

本次完成的是需求梳理和相关文献核查，没有修改训练实现或提交新实验。会议年份以论文或官方会议页面为依据；例如CoTrans为CIKM 2024，CDRIB为ICDE 2022。文献中的效果和理论条件不自动构成LIST的实验证据或创新性保证。
