# 实验进度与分析（整理于 2026-09-21）

本报告汇总截至 2026-09-18 完成的实验与审计。核心状态是：代码和探索性实验已完成，
但发现数据污染及对照不足，尚未完成清洗后重跑，不能宣称方法优于合理的单域基线。

## 1. 问题和访问条件

希望在不能读取源域原始交互、参数、embedding 或梯度的迁移阶段，利用普通推荐
服务的输出进行跨域冷启动评分预测。源模型预训练仍然使用源数据；source-free
限定的是迁移方可获得的信息。访问限制不自动构成差分隐私或更强隐私保证。

当前模拟 API：已有源用户 ID → Top-100 物品 ID＋原始预测分数。每个重叠用户查询
一次，包含目标冷启动用户；不滤除源域已交互物品，不裁剪分数。保留跨域用户身份
对应。List 只用 ID 和排名，普通蒸馏使用 ID 和分数。

这仍是较宽松的实验条件：服务方与迁移方在一台机器上模拟，已有用户可查询，源
模型为 MF。普通蒸馏有 Landlock 边界；List 原实验靠显式输入路径隔离，后续进行了
受控读文件审计。此工作尚未证明面对任意真实平台、未知模型或隐私攻击的有效性。

## 2. 数据和固定设置

Amazon Reviews 2014 5-core，Books / Movies_and_TV / CDs_and_Vinyl；任务是已观察
评分的 MAE、RMSE 预测，不是 Top-K 排序评估。

| 任务（seed 2020） | 重叠用户 | 冷启动用户 | 目标训练评分 | 测试评分 |
|---|---:|---:|---:|---:|
| Book→Movie | 37,388 | 7,478 | 1,541,404 | 156,129 |
| Movie→Book | 37,388 | 7,478 | 8,645,832 | 252,209 |
| Movie→Music | 18,031 | 3,606 | 1,003,963 | 93,629 |

β=20% 指重叠用户中被留作目标冷启动测试的比例；这些用户的全部目标评分不参与
目标训练。按官方 mapper/split/save 划分，保存 ID 映射。固定种子与 PYTHONHASHSEED。
不同任务没有共享同一数值 ID 的语义，必须使用各自的映射。

MF：维度10，Adam lr=.01，weight decay=0，源域/目标域各10轮。PFCDR 反演300步、
batch=200、lr=1e-4、weight decay=1e-4、目标评分5；原型映射10轮、lr=.005。
保持官方 MF 硬编码投票70000的行为。使用经过数值检验的池化和投票计算优化。
EMCDR：官方无偏置线性映射、embedding MSE、batch=128、Adam lr=.01、10轮。

List：自行随机初始化的源物品32维向量，归一化 1/log2(rank+1) 加权池化，
MLP 32→64→32、ReLU、dropout=.1。预测为目标训练均值＋物品偏置＋用户/物品内积。
Adam lr=.001，weight decay=1e-5，batch=2048，10轮。无独立用户ID向量、无蒸馏损失。
使用全部目标训练评分；无源列表的目标用户以零用户表示训练物品偏置。

主结果一律固定第10轮，不挑选最低测试误差。仅有限种子，尚未做正式验证集调参、
多次训练稳定性或完整机制实验。

## 3. 效果汇总与需要修正的判断

| 任务 | EMCDR MAE | PFCDR-WB | 普通蒸馏＋PFCDR | List | 目标物品均值 |
|---|---:|---:|---:|---:|---:|
| Book→Movie | 1.176062 | 0.967869 | 1.049850 | 0.858137 | **0.833428** |
| Movie→Book | 1.119263 | 1.077062 | 1.279025 | 0.799103 | **0.787448** |
| Movie→Music（有污染） | 1.653422 | 1.639227 | 1.649448 | 0.761368 | **0.741995** |

物品均值使用每次相同的 train_tgt.csv 计算、在同一个 test.csv 上评估，不读测试
评分估计均值，不训练任何 embedding。其 RMSE 也在三组上优于 List。

最初 Book→Movie 的官方 TGTOnly MAE=4.178897；它用未经训练的随机冷用户向量
打分，没有均值回退。WB 超过这个 TGT 不能证明其超过合理的目标单域方法。原先
基于该 TGT 算出的增益和97.45%恢复率，只描述这个弱参照，不支持充分的迁移结论。

Movie→Music seed=2021 新划分：WB MAE=1.870619，List=0.752058，物品均值=0.746992。
训练评分中位数为5；始终预测5的 MAE 在 Music 两个种子分别为0.709524/0.700783，
但 RMSE 更差，说明必须同时关注评分分布、指标和个性化能力。

## 4. 耗时（不能混合口径）

seed=2020，从已经划分的数据开始，包含必要的模型训练及迁移流程，不含 raw
解析/划分。EMCDR 与 List 为阶段日志合计估算；WB 后两组有完整阶段计时。

| 任务 | EMCDR | PFCDR-WB | List |
|---|---:|---:|---:|
| Book→Movie | 约7分35秒＋未记录开销 | 至少40分32秒 | 约6分58秒＋未记录开销 |
| Movie→Book | 约7分21秒 | 34分13秒 | 约2分38秒～2分54秒 |
| Movie→Music | 约1分29秒 | 5分53秒 | 约1分03秒～1分11秒 |

EMCDR 本次仅补训练映射，实测12.56/11.59/6.10秒，表中另计已有预训练耗时。
Book→Movie 早期缺部分加载/保存和 WB 映射阶段计时，因此不伪造精确总值。

seed=2021 完整独立重跑 Movie→Music：两条路线分别从同一原始gzip文件解析，
不共享中间数据、权重、查询或原型，串行运行。WB=417.84秒（6分58秒），
List=115.12秒（1分55秒），约3.63倍。包括源模型训练和List重新生成Top-100。
两个独立训练的源模型权重相同、独立划分相同；不含下载，不清空OS页缓存。
两算法模型、batch、评估频率和保存频率不同，这不是同结构的内核性能比较。

## 5. 审计结果：存在真实污染，但未发现学生直接读取测试标签

Movie/Music 共有2,441个原始物品ID。seed2020有5,577/93,629条目标测试记录已在
源训练集，seed2021有5,236/90,192条。重新读取raw确认这些记录的评分、时间戳、
评论正文和标题全部相同。这是跨类别重复评论，不仅是同用户对同一物品的新评价。
所有使用相同源模型的实验均受影响。Book/Movie原始物品ID无交集。

只在非重复测试子集上重算，List误差变化不大（2020为0.762070、2021为0.751203），
但这不能代替清洗后重训：源模型仍已经训练过污染数据。

通过的代码核验：

- 目标训练/测试用户交集为0；从划分前数据和映射重建的记录完全一致。
- 预测、用户、物品、标签逐行对齐，1D误差没有广播错误。
- 独立实现前向计算重现预测，最大差异约1.2e-6。
- 每个实验抽查32个用户，API列表分数符合源模型输出。
- 两次随机初始化学生训练，仅打乱测试标签（52,259行变化），启用确定性计算后
  最终所有参数及预测完全相同。运行时禁止 torch.load，禁止模型保存前读测试文件。
- 完整raw复跑保存的脚本哈希与审计时一致，未发现偷偷加载旧学生权重。

列表词表由所有查询用户（含测试用户）的源列表构建，是当前协议下的无标签
传导式信息，不能直接宣称严格归纳泛化。也没有按时间限制源交互先于目标交互。

结论：代码的直接标签泄漏检查通过不代表数据协议干净。原先对“超过WB即有明显
优势”的解读过强；当前更有价值的发现是基线不足和数据污染，必须先修正。
