# LIST 共现聚类：簇数搜索

## 本轮结果

**在预设簇数1、2、3、4、8、16中，两个β都由验证集选中了1簇。没有发现增加簇数能改善当前方案的证据。** 单簇表示全部已知源物品仍汇总成一个向量，因此这个结果支持继续保留全局聚合主版本，而不是把本轮称作多簇方法的成功。
两卡Slurm作业8711已完成，耗时29分48秒，退出码0。36个候选验证训练、72次聚类配置、12个最终重训模型完成；42条选模记录及最终指标的独立审计全部PASS。三簇条件的六组验证预测与8708完全一致，选轮数和λ也一致。

### 验证选定后的测试结果

各模型三个种子的测试指标均值，越低越好。普通均值与历史方法为冻结参照；本轮没有评价所有候选C后再选测试最优。

| 方法 | β20% MAE | β20% RMSE | β80% MAE | β80% RMSE |
| --- | ---: | ---: | ---: | ---: |
| 普通物品均值 | 0.828612 | 1.074618 | 0.840744 | 1.097641 |
| 原有全局LIST | 0.808497 | 1.056126 | 0.833717 | 1.089396 |
| 上一轮三簇聚类 | 0.809601 | 1.057300 | 0.834123 | 1.090821 |

单簇仍明显超过普通均值与自身错配列表对照。这延续了源信息有帮助的结论；它不支持“需要拆分多个簇才有效”。
相对原有全局LIST，单簇的平均RMSE仅降低约0.000095和0.000093；β20% MAE反而增加约0.000210。β20%的RMSE差异区间跨零；β80%的RMSE区间虽在零以下，但幅度极小。单簇与原全局模型的未知源ID处理等细节不同，不能将这些微小差异归功于多簇聚合。
下表为本轮单簇减原全局LIST，负数代表单簇更好：

| β | ΔMAE [95%区间] | ΔRMSE [95%区间] |
| --- | --- | --- |
| 20% | +0.000210 [+0.000018, +0.000400] | -0.000095 [-0.000273, +0.000071] |

区间按测试用户重采样2000次，条件于三个种子各自已固定的源列表、训练模型和同一用户划分，未校正多重比较。历史测试已多次使用。
这轮否定的是“只把当前硬聚类方案的簇数调大就能获得更好验证效果”这一具体期待，不是否定所有聚类。不同簇数同时改变编码器参数量，且训练预算最多10轮。尚未验证其他特征、软分组、目标相关簇选择或更长训练预算。当前建议保留原全局LIST，不再把单纯增加簇数作为首要优化方向。

## 搜索规则

在现有 Music→Movie 去重任务上固定搜索簇数 **C∈{1,2,3,4,8,16}**。C 是聚类数量；源列表长度始终为 Top100。

每种簇数在 β=20%、80% 各运行三个种子（2020/2021/2022），共36个候选验证训练。每个种子仍按验证RMSE选择epoch0–10及λ∈{0,0.25,0.5,0.75,1}，然后对每个C求三个种子的最佳验证RMSE均值。每档β选择均值最小的同一个C；如完全相同则选更小的C。两个β可选出不同簇数。测试集不参与选择。

本轮不会把全部C在测试集上的最优值当作最终成绩。完成验证选择后，只评价选中C、单簇基线和选中C的必要对照。旧三簇及现有全局LIST作为冻结历史参照。

## 保持和改变的内容

| 项目 | 设置 |
| --- | --- |
| 数据及源服务 | 现有Music→Movie去重任务、同一DNN Top100、同一用户划分 |
| 聚类特征 | 复用8708按训练用户构造的归一化共现SVD32特征；各C完全相同 |
| 聚类拟合范围 | 选模用inner_train特征；全量重训用outer_train特征；验证/测试用户不参与对应拟合 |
| 聚类算法 | KMeans，n_init=10，max_iter=300，random_state=20260925；仅改变C |
| 簇编号 | 按训练log出现频次的簇均值排序，避免任意编号；不使用目标标签 |
| 聚合 | 每簇按绝对排名权重归一化，拼接C个32维向量；空簇为零 |
| 编码器 | C×32 → 64 → 32；dropout0.1 |
| 预测 | 普通目标物品均值 + λ×LIST修正 |
| 训练 | Adam，lr0.001，weight decay1e-5，batch2048，最多10轮 |
| 初始化 | 共享的源/目标物品嵌入等参数与旧模型一致；C>1沿用三簇版第一层初始化程序；C1保留原全局第一层初始化 |
| 未知源物品 | 当前训练列表中未见的ID不进入聚合；沿用8708规则 |
| GPU | Slurm8711，两个GPU分别负责两档β |

| C | 编码器输入维度 | 相对全局模型增加的参数 |
| --- | ---: | ---: |
| 1 | 32 | 0 |

隐藏层宽度保持64，因此簇数增大也会增加参数；不能把变化完全归因于分组粒度。单簇与旧全局LIST的训练结构相同，但验证/测试列表中未知源ID的处理不同，不能直接把两者当作完全相同的模型。

## 选中配置的对照

每档β都重训选中的C和C1的真实列表模型；选中C另跑用户错配列表对照。若选中C>1，还跑按每用户簇大小匹配的随机分组对照；若C1胜出，随机簇归属与原分组完全相同，省略这一重复。

随机对照与选中C具有相同参数量、全部初始参数、每用户各组数量及未知掩码。用户错配使用8650的固定组内置换。对照的epoch和λ各自由同一个验证集选择。最后从原初始化在全外层训练集重训，最终训练不沿用内层已训练的参数。

## 检查与边界

GPU自检覆盖所有六种C：显式加权聚合一致、空簇/未知源用户回退、每簇梯度、初始均值输出、增加参数公式、C1原初始化、C3与8708原实现一致。

评价前校验全部候选的验证最优选择、平均验证选C、模型和特征哈希、选中配置重训及同容量对照。所有新模型冻结后才打开测试标签。最终还有独立指标、均值和选择记录核验。

这是历史数据上的后续探索，不是全新盲测。最优C指当前特征、模型和最多10轮预算下的验证选择，不是所有训练预算或全部聚类方法的普遍最优簇数。三个种子共享用户划分；置信区间条件于这些已训练模型和固定划分。
