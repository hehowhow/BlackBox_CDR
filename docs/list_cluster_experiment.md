# LIST 源物品共现聚类实验

## 结果与结论

**共现聚类没有整体超过现有满意版全局 LIST，本轮不替换主版本。** 作业8708已完成，两张GPU、8分15秒、退出码0；24个最终模型、12次聚类拟合及两层独立审计全部PASS。

三个种子指标的算术平均，越低越好；不是集成模型。标准差、逐种子结果及完整历史对照见运行目录中的报告和CSV。

### 聚类本身的诊断

| β | 种子 | 内层/全量聚类一致性 ARI | 测试列表未知物品比例 | 三簇物品数 |
| --- | --- | ---: | ---: | --- |
| 20% | 2020 | 0.068 | 0.088% | 2149 / 4621 / 2267 |
| 20% | 2021 | 0.732 | 0.089% | 4393 / 2047 / 2225 |
| 20% | 2022 | 0.780 | 0.098% | 5316 / 2541 / 2429 |
| 80% | 2020 | 0.601 | 0.386% | 3740 / 1639 / 1703 |
| 80% | 2021 | 0.431 | 0.378% | 3622 / 1569 / 1550 |
| 80% | 2022 | 0.248 | 0.433% | 4330 / 1878 / 1788 |

ARI比较内层拟合与全量重拟合时共同已知物品的分组；1表示完全一致，接近0表示一致性接近随机基准，已排除简单交换簇编号的影响。部分分组变化较大，值得后续关注。但β20%种子2020的ARI最低，其评分结果反而是聚类版三个种子中最好的，所以当前证据不能把性能未提升直接归因于聚类不稳定。
所有最终聚类的测试列表未知条目比例低于0.44%，没有测试用户的整张列表都未知。簇对物品log出现频次方差的解释比例约0.06%–2.25%；该诊断不能证明热门偏差完全消失，也不能证明簇对应真实音乐类别。

可能原因仍是待验证假设：三类硬分组过于粗糙；源推荐共现所形成的分组未必是最利于电影评分预测的分组；独立归一化和压缩可能损失簇占比或跨簇联系。本轮没有搜索簇数，也没有测试软聚类或目标电影相关的簇选择。
若继续聚类方向，可以优先检验允许物品部分属于多个簇的软分组，并保留同参数量与随机对照，而不是仅依据测试表现反复更换K。当前结果不支持直接替换现有主版本，也不等于否定全部聚类方法。

## 固定设计

本轮在 Music→Movie 去重任务上测试：用源物品在训练用户 Top100 中的共同出现关系分组，是否比全局聚合、按排名分段更有效。保留普通物品均值加 LIST 修正的评分方式；没有叠加额外残差分支。

数据、源 DNN Top100、用户划分、训练配置继承实验 8650；排名分段对照引用实验 8703。新实验通过两卡 Slurm 作业 8708 执行，两个 GPU 分别处理 β=20% 和 β=80%。β为测试冷用户占重叠用户的比例。

## 怎样聚类

1. 只取当前训练重叠用户的源域 Top100。物品×用户稀疏矩阵中的值为 `1/log2(rank+1)`，未被返回的位置为零。这是 API 推荐出现关系，不是真实点击/评分矩阵。
2. 对每个物品的行向量做 L2 归一化，减少向量长度与出现频次的直接关系。
3. 使用 TruncatedSVD 降到 32 维，`n_iter=7`，再对降维后的物品向量做 L2 归一化。
4. 使用 KMeans 聚成三个簇，`n_init=10`、`max_iter=300`；聚类及 SVD 的随机种子固定为 20260925。没有搜索簇数、降维维度或聚类参数。
5. 仅为稳定簇编号，按各簇训练出现次数的平均 `log1p` 从小到大排序；聚类本身使用完整共现表示，不是按频次分桶。
6. 按 ID 将每个用户列表里的源物品放入对应簇。每簇分别按原始绝对排名权重归一化汇总，三个32维向量拼成96维，经96→64→32网络编码，再与目标物品向量点积。

内层选择阶段只用 inner_train 用户拟合 SVD 和聚类；最终全量重训时用 outer_train 用户重新拟合，然后从相同参数初始化重新训练 LIST。验证和测试用户不参与对应阶段的聚类拟合。

词表沿用既有 API 快照中的 ID 编码，因此知道测试列表出现了哪些 ID；但训练列表里从未出现的物品标为未知（-1），不参与任何簇的聚合。空簇为零；一个用户若没有任何已知物品，其修正为零。源簇表示不是教师内部嵌入，也不能未经验证就解释成音乐类别。

## 对照与公平性

| 项目 | 固定设置 |
| --- | --- |
| 主方案 | cooccurrence：按源物品共现聚类分组 |
| 新随机对照 | size_matched_random：对每个用户的已知源物品随机置换簇标签，严格保留该用户三个簇的物品数量和未知位置 |
| 用户错配对照 | 两种新方案均运行 real/shuffled；shuffled 在原内层训练/验证/测试组内错配用户完整列表，使用8650相同置换 |
| 旧方法 | 普通物品均值、现有满意版全局 LIST、排名分段 LIST；完整表还携带旧 EMCDR/PFCDR 等结果 |
| 测试冷用户比例 | 20%、80% |
| 模型种子 | 2020、2021、2022 |
| 向量维度 / 隐藏层 / Dropout | 32 / 64 / 0.1 |
| 优化器 | Adam，lr=0.001，weight decay=1e-5 |
| 批量 / 最大轮数 | 2048 / 10 |
| 验证选择 | 验证 RMSE 联合选择 epoch 0–10 和 λ∈{0,0.25,0.5,0.75,1} |
| 最终训练 | 同初始化，在全外层训练集重训所选轮数；λ冻结 |
| 参数量 | 两个新版与8703排名分段版完全一致，比全局LIST多4096个参数 |
| 初始参数和随机性 | 两个新版全部初始参数一致，并与8703一致；共享参数与8650一致；沿用同批次及Dropout种子 |
| 评价顺序 | 12次聚类拟合、24个最终模型全部冻结，再统一读取测试标签 |

匹配大小的随机对照仍保留了聚类得到的用户簇数量信息，目的是检验“组里放哪些物品”的作用；它不是完全消除聚类信息的对照。随机化可能改变每组的排名权重总量。两种新方案都忽略训练未见源ID，与旧方法的处理有所不同，需结合未知比例解释结果。

## 检查与记录

GPU自检包含：显式加权求和与实现一致、空簇和未知源物品回退、三个簇能获得梯度、初始输出等于均值、随机对照组大小一致、参数量和初始化一致。

独立审计重新计算训练集物品均值和测试指标，检查用户划分、验证最优选择、全量重训轮数、冻结顺序；额外重建训练列表稀疏矩阵，验证降维投影、最近聚类中心分配、未知掩码、真实与随机组大小、每模型实际使用的聚类文件哈希。

同时记录每个簇的物品数量、训练列表出现次数分布、用户平均簇大小、空簇比例、未知源ID比例，以及簇对物品对数出现频次方差的解释比例。频次归一化不能保证完全消除热门物品影响，这些诊断不被用于调参。
