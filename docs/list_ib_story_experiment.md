# LIST 信息瓶颈独立叙事线

本轮只增加高斯隐藏瓶颈，不混合聚类、检索、组合记忆或目标条件聚合。任务为 Music→Movie 去重版，沿用作业8650的β20/80与三个模型种子、冻结DNN Top100 ID/rank及普通物品均值。

结构：原排名加权池化32维 → 原Linear32→64与ReLU作为高斯均值 → 新logvar头64→64 → 训练采样 → 原Dropout0.1 → 原零初始化Linear64→32 → 与目标物品点积 → 加上普通物品均值。随机采样位于零输出层之前，因此初始预测在训练和推断中都严格等于物品均值。推断取高斯均值，不做随机采样；新增4160个训练参数。

固定η为0、1e-4、1e-3；方差头初始logvar=-6，限制到[-12,6]。KL按64维求和，对有源列表的交互计入、对没有列表的交互置零，然后按全部训练交互平均；同一用户按交互次数加权，与MSE使用相同权重。η=0是同一随机结构的无KL对照。

其余设置保持8650：embedding32、hidden64、dropout0.1、Adam学习率0.001、weight decay1e-5、batch2048。内层冷用户验证在epoch0..10和λ={0,.25,.5,.75,1}上选最小RMSE；完整训练集重训从原初始化开始。训练时λ=1。

18个候选顺序运行于一张Slurm申请的GPU，全部模型与预测冻结后才打开测试标签。训练进程通过审计钩子禁止访问测试标签、源真实交互、教师权重和教师分数。历史测试集已经反复使用，本轮仍属探索，不据此单独声称增强解释性或鲁棒性。

实验已完成：Slurm作业8763。受账户的作业数和GPU上限约束，外层作业申请两张GPU并运行两条独立叙事线；本IB进程始终只继承其中一个设备（CUDA_VISIBLE_DEVICES=1），18个模型在该卡顺序运行。最初排队的单卡作业8761由协调者取消，未开始训练。

GPU数学自检及独立CPU审计均为PASS。审计核对了18个最终模型均早于测试评估冻结、数据/旧代码哈希、冷用户划分、训练数据普通均值、跨η相同初始化、原LIST共享参数初始化、验证集epoch/λ精确最优、完整训练集重训、未见目标物品回退以及MAE/RMSE和差值的独立重算。

当前没有稳定的整体收益。小η在β20的RMSE比原LIST降低0.000500，但MAE增加0.001451；相对η=0的随机结构对照，RMSE仅再降低0.000372。β80的小η在两项指标上均未超过原LIST，且RMSE比η=0更差。强η则在两种β下均明显损害两项指标。本轮没有进行显著性检验，不能把微小差异表述为可靠提升。

KL约束实际发挥了作用：最终refit轮次中，每个有源列表交互的64维KL之和，跨三个种子的均值如下。该值是目标函数中的变分代理量，不是实测互信息，也不直接测量解释质量。

| β | η=0 | η=1e-4 | η=1e-3 |
|---|---:|---:|---:|
| 20% | 89.73 | 54.19 | 2.80 |
| 80% | 77.24 | 58.49 | 13.13 |

强η在两种β下的全部模型均选到epoch10；β80的所有新版本也都选到epoch10。因此，结论限定为“同样10轮预算与本轮固定参数下，没有得到稳定收益”。不能排除更长训练或其他参数有用，也不能仅凭本结果认定强约束一定删掉了有用信息：过强约束与优化变慢都可能造成表现下降。没有增加普通正则化调参对照，η=0仅用于分离采样结构与KL的增量影响。
