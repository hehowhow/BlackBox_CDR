# 最小实验计划

> 这是最初计划，不代表最新结果；当前任务和审计结论见
> [实验进度与分析](experiment_progress.md)。

## 1. 核对依赖与协议

- 找到并核实 PFCDR、DBGRME 原论文与官方代码，记录 URL、commit、许可证和依赖。
- 核对 Book → Movie、MF、β=20% 的数据版本、评分处理、划分、cold-start 定义、评价用户及 MAE 实现。
- 检查 DBGRME 接口、模型和任务是否兼容 PFCDR；不能仅凭名称假设可以直接拼接。
- 确认允许查询的用户、源物品 ID 范围、Top-K、是否返回分数及训练项过滤规则。固定并记录查询量，不做预算敏感性实验。
- 所有尚未确认的超参数保持待定，不以随意默认值冒充官方设置。

## 2. 建立共同参照

- 固定数据划分、ID 映射、随机种子与评价样本。
- 按官方设置训练一个 source checkpoint，供 WB 和 BB 的 victim 共用。
- 运行官方 TGTOnly 与 PFCDR，保存配置、日志、逐样本预测和 MAE。
- WB 应先显示可辨识的迁移收益，否则无法据此讨论黑盒造成的收益损失。

## 3. 黑盒分支

- source 训练属于服务方准备阶段；迁移阶段不能接触源交互。
- victim 独立封装为推荐接口。提取程序仅能读取获准的用户/物品标识及 API 输出。
- 禁止提取程序读取 victim 参数、embedding、梯度、隐藏表示或源训练交互。
- 独立进程本身不保证文件隔离；实施时需限制文件可见性并审计输入路径。
- 优先使用核实后的 DBGRME 官方 extraction；若接口不兼容，先记录差异和替代依据。
- 用 surrogate 替换 PFCDR 的 source，保持目标侧协议和其他可控条件一致。
- PFCDR 可以读取 surrogate 内部信息，但不得经共享路径或初始化泄漏 victim 内部信息。
- 记录 surrogate 的输出与评分尺度兼容性，区分接口适配错误和真实迁移性能损失。

## 4. 汇总与解释

填写 `results/metrics.csv`，计算：

- G_WB = MAE_TGT − MAE_WB。
- G_BB = MAE_TGT − MAE_BB。
- Gap = MAE_BB − MAE_WB。
- RecoveryRatio = G_BB / G_WB；G_WB ≤ 0 或接近零时不作稳定恢复率解释。

第一轮只回答 Q1–Q3，不扩展方法、机制分析或敏感性实验。单次运行仅用于观察趋势；若声称“明显”或“稳定”，需配对重复种子或相应不确定性证据。一次提取基线的差距不能证明所有黑盒方法的固有性能上限。

仅在首轮结果支持继续时，再考虑 Book → Music 和 Music → Movie。
