**结论：48个模型确实运行并通过指标核验，但原方案没有全部落实。尤其R2信息采集的核心策略尚未实现，固定K实验不能算作R2方法完成。** 先前使用“三条路线全部完成”概括这批工作不准确。

IB的隐藏层方案是为保留“训练采样时也从零修正开始”所作的实现选择。这个理由能解释改动，但不能把两个不同位置、不同维度的KL约束说成原公式的逐项实现。KL归约采用按64维求和、再按训练交互平均，已记录；原文允许实施时明确这种归约方式。

记忆线使用训练用户建表、未知组合置零、单个编码器和评分头等核心约束已经落实。没有在训练前设置覆盖率go/no-go门槛，符合用户“不要考虑太多机制探索、go/no-go条件，直接比较指标”的后续指示，不应被列为执行错误。缺少归因对照则限制了可作出的机制结论。

## 信息采集线为什么是实质偏离

原文R2a明确要求“先读20条 → 判断停止或继续到50条 → 必要时继续到100条”。这个判断模块是方法本身，不是可省略的机制解释实验。

实际 [list_acquisition_story.py](../scripts/list_acquisition_story.py) 的 `DEPTHS=[20,50,200]`、`study='fixed source response depth; no active query or stopping policy'`，以及按K分别创建和训练 `ResidualList` 的流程，直接表明它实现的是固定长度对照。它没有：

1. 根据用户已可见的前缀决定是否继续获取的策略。
2. 在多种前缀长度上训练的共同变长编码器。
3. 固定预算下的随机分配与学习分配比较。
4. 候选集合查询或目标任务导向的查询选择。

Top200由相同冻结DNN导出、前100与旧缓存一致、学生不读取教师分数、选模与指标复算正确，这些都是已有实验的有效性检查；它们不能补足缺失的策略。

分派任务时，主代理主动把R2改成固定K20/50/200以降低复杂度，随后将这批运行概括为三条路线完成。用户要求省去繁重机制探索，并没有要求删除核心优化方法。责任在主代理的方案取舍和完成状态表述，不在子agent按任务执行，也不能用GPU配额限制解释这一方法变更。

## 现有结果能支持什么

- IB结果只评价此次隐藏层VIB变体、三个η和十轮训练预算；不能据此判定整条IB路线无效。
- 采集结果只评价固定列表长度。Top200的局部改善不证明学习型采集有效，其他K不改善也不否定动态采集。
- 记忆结果只评价两个具体字典与融合方案；没有一致改善原版，不等于所有组合记忆方案无效。
- 48组MAE/RMSE和训练记录保持有效。审计文件中的PASS表示已经执行的实验通过相应数据、训练及指标检查，不表示原优化文档的所有功能和对照都完成。

## 补齐R2应实施的最小方法

按原文R2a实现即可，无需同时实现R2b：共同变长LIST编码器在20/50/100前缀上训练；策略只看已获得的前缀，预测继续读取的目标任务收益；策略训练只用训练用户监督，验证集确定参数。测试用户按策略顺序获取，决定继续前不能看隐藏后缀及其衍生特征。

评价应同时包含原版Top100、同一编码器的固定长度、匹配平均返回预算的随机分配与学习分配。报告MAE/RMSE、平均返回条目数和调用数。这些是原方法与必要对照，不能由再次扫描K值代替。当前它们仍未实现或运行。
