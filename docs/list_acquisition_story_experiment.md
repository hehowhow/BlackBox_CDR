# LIST 固定K对照：R2的前置实验

2026-09-25范围更正：本轮没有实现 [原优化文档](list_remaining_optimization_tracks.md) 中R2a的共享变长编码器与停止/继续策略，也没有实现R2b候选集合查询。18个固定K模型已完成，不代表信息采集优化方法已完成。详见 [实施核对](list_implementation_alignment_audit_20260925.md)。

本轮只改变源服务返回的列表长度，测试 Top20、Top50、Top200，并与已冻结的原版 Top100 LIST 比较。它回答“更短或更深的源列表能否改善目标评分预测”，不把固定截断称为主动查询。

Slurm总作业为8763；信息采集分支独占其中一张已分配GPU，分支内部串行训练。结果目录为 `runs/list_acquisition_story_8763/`。本线18个新模型均已完成；导出、初始化、冻结评估和独立CPU审计全部PASS。

## 实验结果

**将Top100扩展到Top200，在β20%上带来小幅改善；β80%上RMSE几乎不变，MAE略差。更深列表没有在两个设置上同时稳定改善两项指标。** 缩短到Top20则在两个设置上都变差。

以下为三个种子各自指标的平均值，不是把三个预测模型集成后计算。MAE/RMSE越低越好；普通均值和原Top100为8650冻结参照。

| 方法 | β20% MAE | β20% RMSE | β80% MAE | β80% RMSE |
| --- | ---: | ---: | ---: | ---: |
| 普通物品均值 | 0.828612 | 1.074618 | 0.840744 | 1.097641 |
| 原版LIST Top100 | 0.808497 | 1.056126 | 0.833717 | 1.089396 |
| LIST Top20 | 0.814098 | 1.058578 | 0.834338 | 1.090433 |
| LIST Top50 | 0.810500 | 1.057239 | 0.833308 | 1.089550 |
| LIST Top200 | 0.806405 | 1.055585 | 0.833955 | 1.089390 |

下面为新版本减原Top100，负数表示改善。

| 列表深度 | β20% ΔMAE | β20% ΔRMSE | β80% ΔMAE | β80% ΔRMSE |
| --- | ---: | ---: | ---: | ---: |
| Top20 | +0.005602 | +0.002452 | +0.000621 | +0.001037 |
| Top50 | +0.002003 | +0.001113 | -0.000409 | +0.000154 |
| Top200 | -0.002092 | -0.000541 | +0.000237 | -0.000006 |

Top200在β20%的三个种子上，RMSE分别下降0.000246、0.001172、0.000204；MAE的平均改善主要来自seed2022，seed2020的MAE略有上升。因此可以说本轮较深列表在β20%的RMSE结果方向一致，但不能把所有指标都说成逐种子稳定提升，也没有据此宣称统计显著。

β80%的Top200与原版RMSE差只有约0.000006，实际可视为持平；三个种子的MAE均略差。Top50在该设置下MAE略好、RMSE略差，也属于指标取舍。三个K版本仍都超过普通物品均值。

这轮支持的具体观察是：Top20不足以保留原Top100的全部预测收益，Top100以外的条目在重叠训练用户较多的β20%设置中仍有少量可用增量；当重叠训练用户更少时，仅增加返回数量没有带来明确改善。后一点与“可用跨域监督限制了新增条目的学习”相容，但本轮没有单独证明这一解释。

本轮完整报告三个预设K，没有用测试结果挑选一个统一最优K。若继续探索这条线，候选重点应当是怎样在固定返回预算下获得更有用的信息，而不是仅把K继续无上限增大；那将是另一个明确的接口和实验设计。

## 固定实验协议

| 项目 | 设置 |
| --- | --- |
| 数据 | Music→Movie 去重版；17,904名重叠用户；复用8650数据和内外层划分 |
| 冷启动比例 | β=20%、80%，表示留出的重叠用户比例 |
| 种子 | 2020、2021、2022 |
| 比较对象 | 原版 `small_task_comparison_8650` 的 `residual_real`，以及普通物品均值 |
| 唯一主要变化 | 源 Top-K 列表深度 K=20、50、200；按当前K重新归一化固定排名权重 |
| 聚合和预测 | 原版排名加权全局聚合→32/64/32 MLP→目标物品内积修正→加普通物品均值 |
| 优化 | Adam，学习率0.001，weight decay 1e-5，batch2048，dropout0.1 |
| 选择 | 验证RMSE选择epoch0–10和λ∈{0,0.25,0.5,0.75,1} |
| 重训 | 从原初始化开始，在完整外层训练集训练被选中的轮数 |
| 评估 | 本线18个新模型全部冻结后才读取测试标签；完整报告三个K，不按测试挑选版本 |

## 源服务与学生隔离

独立教师进程读取原来的冻结DNN checkpoint，对同样的全目录返回Top200。没有重新训练教师，没有过滤已消费物品，也没有向学生传递源评分、教师向量、真实源历史或原始源数据。

导出时逐行核对Top200的前100与历史Top100。如果不同的GPU top-k内核使数值并列项目的顺序改变，只在逐排名评分差不超过4e-6、旧头部仍属于新Top200且完整列表保持排序阈值时保留历史头部；变化数量和最大差异写入导出记录，不静默处理非并列排序漂移。

实际三个种子的原始前100都完全一致，不一致位置和并列修正数均为0；重新导出的Top100文件SHA也与原缓存相同。

教师进程结束后，独立初始化进程只使用合法返回的ID；训练学生只能打开自己对应K的用户列表。审计钩子禁止学生读取其他K的用户列表、`source.pt`、`source.csv`或评分缓存，并禁止训练期读取测试标签。

## 控制词表变化带来的初始化干扰

每个种子共用Top200返回ID的并集作为公共词表，原Top100词表放在前面，新增ID追加。所有K版本因而具有相同参数数量。原版的所有已有源ID向量、MLP参数和目标物品向量逐项保持原始初始化；新增源ID用独立随机种子初始化，避免扩表导致后续目标参数随机数错位。原初始化哈希会与8650记录核对。

公共词表包含Top200额外观测得到的ID集合，这是本轮明确增加的输入条件；较短K版本不会获得这些ID属于哪个用户或位于该用户列表中的什么位置。相比历史K100，公共源embedding表更大；Top20/50未使用的新增行不会提供用户特征。因此不能把表大小变化隐藏起来，三个新版本的完成记录均报告新增参数量。

| 种子 | 原Top100词表大小 | 新增ID数 | 公共词表大小 | 三个新版本各自可训练参数 | 相对原版新增参数 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 2020 | 9,319 | 4,898 | 14,217 | 2,060,832 | 156,736 |
| 2021 | 8,952 | 4,755 | 13,707 | 2,044,512 | 152,160 |
| 2022 | 10,606 | 5,636 | 16,242 | 2,125,632 | 180,352 |

## 查询成本如何解释

本轮实际研究成本是三个冻结教师各导出一次Top200，随后跨β复用，Top20/50由前缀离线得到。实际发生的返回成本按Top200计，不能宣称截断缓存已经节省了网络或真实源服务成本。

实际合计为53,712次按用户计的逻辑查询、10,742,400个返回ID以及3,330,251,424个用户—候选评分。实现会在GPU上按128用户批量评分，所以逻辑用户查询数不等于底层矩阵乘法次数；这些查询在本地冻结教师上完成，没有虚构外部服务的费用或网络延迟。

`query_budget.csv`另外列出“单独部署一个固定K接口”的理论预算：每用户一次逻辑请求、返回K个ID、源端对62,002个候选物品排序。一个用户的源列表由其全部目标物品预测共享，不能按每个目标评分重复收取查询后仍声称每用户只请求一次。

| 独立固定K接口 | 每用户请求数 | 每用户返回ID数 | 每用户评分候选数 |
| --- | ---: | ---: | ---: |
| Top20 | 1 | 20 | 62,002 |
| Top50 | 1 | 50 | 62,002 |
| 原Top100 | 1 | 100 | 62,002 |
| Top200 | 1 | 200 | 62,002 |

Top200要求源服务允许更深返回，属于接口输出深度扩展；不等于读取源分数或教师参数。候选规模相同只表示评分范围一致，不能据此保证完整响应延迟相同。

## 核验与文件

- `scripts/list_acquisition_story.py`：准备、隔离教师导出、共享初始化、训练和冻结后评估。
- `scripts/slurm_list_acquisition_story.sh`：申请单卡时可独立提交；8763中由双卡总作业给本分支分配一张卡后调用。
- `scripts/verify_list_acquisition_story.py`：独立CPU审计，重放epoch/λ选择、重算MAE/RMSE及原版差值、检查前缀和模型冻结时间。
- `per_seed.csv`：每β、每种子、每K的结果与选择参数。
- `comparison.csv`：三种子均值、样本标准差、相对原版的指标差。
- `summary.json`、`verification.json`、`independent_verification.json`：汇总和核验记录。
- `queries/seed_*/complete.json`：导出来源、前缀核对、数值并列记录及实际查询预算。

当前仍使用此前反复探索过的历史测试划分，结果属于探索性比较；三个种子共享同一用户划分。K20/50/200是训练前固定的三种版本，最终完整列出，不将测试最小值包装成预先确定的唯一方案。
