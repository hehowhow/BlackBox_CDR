## 检查的实现与数据流

`scripts/audit_list_pipeline.py:32` 从 `train_tgt.csv` 读取训练数据。
第 70—77 行计算全局均值、中位数、物品计数和评分总和。

对测试用户 u、目标物品 i，物品均值预测为：

```
sum(train_tgt 中物品 i 的评分) / count(train_tgt 中物品 i 的记录)
```

有数组位置但没有训练记录的物品回退为目标训练集全局均值。
预测只查询测试物品 ID；测试评分仅在 `metric(pred, y)` 中用于计算误差。
虽然审计函数提前读取测试文件，但没有把测试评分用于计算均值。
源域文件、源域模型、测试用户评分历史均不是这个预测公式的输入。

划分依据是用户：`external/PFCDR/preprocessing.py:73` 抽取冷启动用户，
其所有目标评分进入测试集，其余目标用户的评分进入训练集。
同一物品由其他训练用户评价是允许的信息；这是用户冷启动协议。

## 发现的问题与边界

1. **跨域数据重复仍存在。** 使用原始用户/物品 ID 对照，Movie→Music seed2020
   的 5,577 条测试记录、seed2021 的 5,236 条测试记录在源域出现，评分也相同。
   本次复核的是用户/物品/评分三元组；仓库原有审计还报告了原始评论文本重复。
   均值基线不读源域，因此该问题不构成它的直接输入泄漏；使用源域的模型实验
   需要先清洗再重训。不能从重复数据上误差的大小推断污染影响的方向或幅度。
2. **数组上界缺少回退。** 如果新测试物品 ID 大于训练最大 ID，原代码会
   `IndexError`。合成边界样例已复现。本次四组未触发，既不泄漏标签也不影响
   已记录指标；以后推广到冷物品时应补全越界的全局训练均值回退。
3. **协议不是时间外推。** mapper 使用全量用户/物品集合做 ID 编码，划分为
   随机用户留出，没有要求源域和其他用户的目标域交互发生在测试时刻之前。
   这限定了结论适用范围；如果研究未来推荐，需要另设时间切分协议。
4. **均值不是 MAE 的最优常数选择。** 给定分组，均值最小化训练平方误差，
   中位数最小化训练绝对误差。Music seed2020 的训练全局中位数为 5，固定预测
   5 的 MAE 为 0.709524，但 RMSE 为 1.269873。应明确优化的是哪个指标，
   并避免用观察测试结果来挑选最终基线或超参数。

## 对研究结论的含义

这些结果足以质疑所测方法在当前冷启动评分预测协议中的增益，也支持把物品均值
作为必须认真对照的目标侧基线。它们不足以否定所有跨域推荐任务。
物品均值不含个性化信息；在当前分布和 MAE/RMSE 下，所测模型的个性化部分
尚未产生超过目标物品统计量的净收益。原因可能涉及源信号不足、估计误差、
模型或优化问题；本次均值审计不能在这些原因之间作出判定。

进一步实验应先处理重复数据，建立独立验证集，冻结测试集；再比较“物品均值”
与“物品均值 + 源域个性化残差”，配合重新训练的源用户信息置换对照和多个种子。
即使这一比较继续失败，也应把结论限定为已检验的任务、数据和方法。
上一轮 1 epoch / 2 次反演的 Slurm smoke test 仅验证运行，不提供效果证据。
